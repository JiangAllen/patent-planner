# 簡報素材總覽（從這份開始看）

鴻海二面（2026-10-16）20 分鐘簡報的基礎。所有數字都已核對過 `reports/scored/`，可以直接使用。

## 1. 一句話

用合成資料對 4B 模型（Qwen3-4B-Instruct-2507）做 QLoRA，讓它當專利答辯 Agent 的 Planner。微調後：
- 熟題型從 61% 進步到 99–100%。
- 沒看過的題型從 22% 進步到 44%；第二輪補資料後再升到 54%。

結論：模型能把學過的元件重新組合，但不會自己產生訓練資料中從沒出現過的元件。

## 2. 答對題數（主指標 plan exact match，整份計畫全對才算 1 題）

| run | 熟題型 test_id | 沒看過題型 test_ood |
|---|---|---|
| zero-shot | 50 / 121（41%） | 31 / 149（21%） |
| few-shot | 74 / 121（61%） | 32 / 149（21%） |
| qlora-r16 | 120 / 121（99%） | 66 / 149（44%） |
| qlora-r16-v2 | 121 / 121（100%） | 81 / 149（54%） |

配對檢定（同一批題目逐題比較）：
- v1 對 few-shot：OOD +0.228 [+0.161, +0.295]
- v2 對 v1：OOD +0.101 [+0.040, +0.161]

兩組差異的信賴區間都不包含 0，代表進步是真的，不是運氣。

## 3. 輔助指標（test_ood）

| run | JSON 合法 | action 準確 | tool F1 | 誤用干擾工具 ↓ | 字面參數 | 引用參數 | 相依 |
|---|---|---|---|---|---|---|---|
| zero-shot | 0.953 | 0.664 | 0.727 | 0.280 | 0.705 | 0.353 | 0.430 |
| few-shot | 0.960 | 0.638 | 0.760 | 0.270 | 0.846 | 0.433 | 0.590 |
| qlora-r16 | 1.000 | 0.953 | 0.920 | 0.170 | 0.948 | 0.520 | 0.690 |
| qlora-r16-v2 | 1.000 | 0.973 | 0.914 | 0.220 | 0.942 | 0.693 | 0.760 |

怎麼解讀：
- 工具選對（F1 0.92）、字面參數填對（0.94）、要不要動作判斷對（0.97），都已經很高。
- 最弱的是**引用參數**（0.52 → 0.69）與**相依關係**，也就是「把上一步的哪個結果接到下一步」。這是剩下失敗的主因。

熟題型的完整數字（全部接近 1.0）見 `reports/results.md`。

## 4. 簡報故事線（建議）

1. **問題**：專利答辯需要多步驟工具呼叫，Planner 要輸出可執行的 DAG。→ `docs/design.md`
2. **資料**：30 個模板反向生成，再用 LLM 改寫；6 種結構只放在 OOD 測試集，訓練時完全看不到。→ `docs/design.md`、`data/manifest.json`
3. **Baseline**：few-shot 讓熟題型進步，但 OOD 沒進步；而且拒絕題反而從 80% 掉到 0%（範例讓模型「什麼都想做」）。
4. **QLoRA**：熟題型幾乎全對，OOD 翻倍。→ `reports/figs/exact_by_category_test_ood.png`
5. **Error analysis**：失敗集中在 3 種結構。原因是訓練資料缺某些元件（例如答辯書從不帶修正內容）。→ `reports/error_analysis.md` 第 1–5 節
6. **第二輪驗證假設**：補元件後元件學會了（0/25 → 16/25），但組合與兩跳推理沒有轉移。→ `error_analysis.md` 第 6 節、`docs/plan-v2.md`
7. **限制與下一步**：見第 5 節。

## 5. 一定要主動講的限制

1. 熟題型 99–100% 代表題目太簡單（與訓練資料同模板），只能證明格式學會了；重點看 OOD。
2. 全部是合成資料，沒有在真實請求上驗證過。
3. 每組只訓練一次（單一 seed），不知道重新訓練的波動有多大。
4. 評分很嚴格：把引用寫在句子裡就算錯。放寬後 v1 的 OOD 是 0.517、v2 是 0.617（`evaluation/sensitivity.py`）。
5. 熟題型的 clarify 只有 4 題，所以 clarify 改用合併的 n=28 報告。
6. v2 是看了 OOD 的失敗原因才補資料，54% 偏樂觀。
7. 改寫有約 2% 的錯字（「答辨」）。刻意保留，當作真實使用者的雜訊。
8. 改寫品質：自動守門保證 slot（案號、日期、指示文字等）逐字保留，不通過就退回原句；人工抽查 90 筆只做了定性瀏覽，除 1 筆術語偏移外未發現問題，但沒有量化的偏移率。
